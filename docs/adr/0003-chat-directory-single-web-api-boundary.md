# ADR-0003: Web API доступен только через ChatDirectory, наружу — DTO и одно исключение WebApiError

- **Статус:** Accepted
- **Дата:** 2026-10-07
- **Контекст решения:** архитектурное ревью 2026-10-06, кандидат №2 «Web API клиент: из shallow — в глубокий каталог чатов» (карточка №2)
- **Связанные материалы:** `GLOSSARY.md` → *Chat*, *Chat Listener*

## Контекст

`ChatWebService` был shallow-модулем: 4 метода почти так же сложны, как реализация; знание об одном сценарии «как получается инфо о чате» размазано по 5 файлам (`services/web.py`, `services/converters/chats.py`, `services/constants.py`, `exceptions/chats.py`, `dtos/messages.py`). Наружу торчали `httpx.Response` и сырые `dict`; на каждый эндпоинт — свой класс исключения и копипаста `if not response.is_success`; httpx ходил без таймаутов (зависший ответ подвешивал и бота, и consumer'а).

## Решение

**Один глубокий модуль `ChatDirectory`** (`app/services/web.py`):

- наружу — четыре сценария (`get_all_chats`, `get_chat_listeners`, `add_listener`, `get_chat_info`), DTO и **единственный тип ошибки `WebApiError(method, endpoint, status_code, detail)`**;
- внутри — httpx, URL'ы, конвертация ответов в DTO, разбор `detail` FastAPI (строка/объект/не-JSON), явный `REQUEST_TIMEOUT = 10.0`;
- конвертеры, константы эндпоинтов и зоопарк исключений удалены — они внутренняя деталь модуля;
- **тестируемый seam — транспорт**: контейнер отдаёт `httpx.AsyncClient`, в смоуках это `MockTransport`; сам модуль не мокается.

## Альтернативы

**B. Сохранить семейство исключений по эндпоинтам** (`ChatListRequestException`, `ListenerAddRequestException`, …). Отклонено: специфичность сообщений покупается зоопарком, который переносит ветвление в `handlers/errors.py` (deletion test не проходил — сложность переезжала, а не концентрировалась); различие эндпоинтов и так сохранено полем `endpoint`.

**C. Оставить конвертеры отдельным модулем** (`services/converters/`). Отклонено: они нужны только внутри модуля; отдельный файл — это интерфейс, у которого нет второго потребителя.

## Последствия

**Плюсы:**

- новый эндпоинт = один метод модуля, без пары «конвертер + исключение + константа»;
- вся логика HTTP проверяется без сети и без мока самого модуля;
- таймауты и разбор ошибок существуют в одном месте.

**Минусы / обязательства:**

- все потребители обязаны ловить `WebApiError` (сейчас это `handlers/errors.py`); ловить отдельные исключения по эндпоинтам больше нельзя;
- поле `status_code = 0` зарезервировано под сетевую ошибку (ответа не было вовсе).

## Когда пересматривать

Появился второй внешний API (не Web API RouteRelay) или понадобились политики ошибок per-endpoint (ретраи, бэк-офф, circuit breaker) — тогда граница либо дублируется для нового API, либо обобщается.
