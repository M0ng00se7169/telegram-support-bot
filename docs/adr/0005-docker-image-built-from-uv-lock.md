# ADR-0005: Docker-образ собирается из uv.lock, база — python:3.12-slim-bookworm

- **Статус:** Accepted
- **Дата:** 2026-10-07
- **Контекст решения:** двойной сбой сборки/запуска consumer'а 2026-10-07 при попытке поднять его в Docker
- **Связанные материалы:** `Makefile`, `docker_compose/*.yaml`, `uv.lock`

## Контекст

Сборка падала дважды, оба раза расхождением образа с окружением разработчика:

1. `python:3.12.1-slim-bullseye` → `apt-get install` отдаёт 404: репозитории bullseye (EOL) больше не отдают пакеты `-dev`, которые запрашивает Dockerfile;
2. `uv pip compile pyproject.toml -o requirements.txt` собирал requirements **без учёта `uv.lock`** и ставил `faststream 0.7.7` рядом с `dishka 1.4.0` — consumer не стартовал: `RuntimeError: FastStream 0.7.7 version not supported`.

Локальное окружение при этом жило по lock (faststream 0.5.28), т.е. образ и dev-окружение расходились по тем же пакетам.

## Решение

- builder экспортирует зависимости **из `uv.lock`**: `uv export --no-dev --no-hashes --no-emit-project -o requirements.txt`;
- база — `python:3.12-slim-bookworm` (поддерживаемый дистрибутив, рабочие apt-репозитории для тулчейна сборки).

## Альтернативы

**A. Запинить версии прямо в `pyproject.toml`.** Отклонено: дублирование с `uv.lock`, который и есть источник пинов; пин в pyproject начинает врать при следующем `uv lock`.

**B. Ставить зависимости через `uv sync --frozen` прямо в образе.** Отклонено на данном этапе: меняет раскладку (`.venv` вместо system site-packages) и требует правки PATH/CMD во всех compose-файлах; `uv export` даёт ту же воспроизводимость одной строкой в builder-стадии.

## Последствия

**Плюсы:**

- в образ попадают ровно те версии, что в `uv.lock` и у разработчика (faststream/dishka согласованы);
- обновление зависимостей происходит в одном месте — через `uv lock`.

**Минусы / обязательства:**

- образ не получает новых версий «сам», только вместе с обновлением lock-файла;
- добавление зависимости в `pyproject.toml` без обновления `uv.lock` теперь ломает сборку образа (раньше — нет) — это и есть желаемое поведение.

## Когда пересматривать

Если проект перейдёт на распределённую установку зависимостей в образе (`uv sync --frozen` с layer-caching по lock) ради скорости сборки — заменить export на sync, сохранив требование «только из lock».
